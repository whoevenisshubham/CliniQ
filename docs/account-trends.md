# Patient account and measured trends

`/patient/account` now uses the scoped `/api/account` handler. The retained `PatientAccountClient` and `FamilyHealthGraph` remain available as historical source; their mock fallback data and inferred family connections are not used by this path. The new family diagram adapts the generation layout and draws only explicit parent IDs, with an editable list available at every size.

Profile, language and purpose preferences are patient-owned. Staff cannot edit them. There is no ownership, Auth email, staff role or verified ABHA mutation. DOB, phone, blood group and medical context can remain unknown. Allergies and conditions here are explicitly patient-entered context, not clinician approval. All writes require the saved account revision and an actor-scoped stable operation key. Corrections append immutable before/after history. Existing patient IDs, demographics, consent rows and family history are preserved by the additive upgrade.

Purpose preferences reuse `data_consents`. Historical rows remain labelled historical; current explicit preferences use a separate managed row per purpose. These preferences neither grant document access nor activate research, insurance, public-health or WhatsApp transfers. No external consumer is connected.

Family entries reuse `family_members`. Parent references must belong to the same patient, active entries cannot link to archived parents, cycles are rejected and paths are bounded to sixteen parent links. A parent with active children cannot be archived through the patient transaction. Each account retains at most one hundred family entries. Archive retains the original entry/history. A family entry does not link to that relative's Auth account or imply genetic risk.

Trends use only authorized approved EMR snapshots. Every measurement keeps its numeric value, exact unit, observation date and source version. Amendments preserve prior observations as superseded-source history; only current, dated, finite values are eligible for plots, grouped separately by exact name and unit. Two measurements are required per plot. Missing values are never zero and undated values stay in the source table. This view returns the latest two hundred source entries, not an unlimited lifetime summary; it does not compute health scores, conversion assumptions or predictions.

The new real-Auth account integration suite exercises profile persistence/replay/conflicts, staff/cross-owner denials, purpose preference history, family reference/cycle/archive constraints, returning sessions and measurement version preservation. Read the tested commit's CI result before treating these behaviors as accepted. Listening browser, hosted account/schema and actual zoom coverage remain separate.
