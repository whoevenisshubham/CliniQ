# Vercel Preview execution

Only `cliniqplus-v2`, Preview, exact `codex/v2-containment` branch and `https://cliniqplus.vercel.app` are in scope. Supabase remains the existing isolated project. No production promotion, provider calls or new provider allowances are part of this change.

Document commits await one scoped durable job on Vercel. Work never depends on a detached promise or an HTTP202. SQL owns claims, lease expiry, attempts, source revisions and publication fences. Upload/replacement/retry/delete pass their document ID; AI jobs pass their job ID. Failure leaves durable state available for reconciliation. Patient owners can select **Resume saved processing** for queued/parsing versions. This endpoint rechecks real Auth, patient role and document RLS before selecting one eligible job. It cannot claim another owner's work.

`GET /api/internal/document-worker` gives authenticated build/asset/disabled-flag diagnostics. `POST` accepts an empty body only, reconciles recorded orphans and executes at most one job. Both require the existing private dispatch secret with constant-time comparison. No public worker secret, arbitrary caller job selection or unauthenticated claim is accepted. Keep deployment protection enabled.

Vercel Preview does not run Vercel Cron. Consequently expired jobs and cleanup require another authorized invocation; unattended periodic recovery is **not accepted**. One concrete zero-spend option is an explicit GitHub Actions schedule every 15 minutes, one protected POST per run, repository concurrency 1, existing dispatch secret plus a Vercel automation-protection credential in Actions secrets. This option is prepared only: protection credential access and account eligibility must be reconciled before enabling it. It must never disable deployment protection or target production.

Affected routes declare Node and 120 seconds. The project must permit that duration (Fluid Hobby supports up to 300 seconds); deployed runtime/memory verification remains separate. Existing uploads are at most 4 MiB plus bounded multipart overhead, below Vercel's 4.5 MB request ceiling. Parser workers retain 256 MiB old-generation and 30-second deadlines. OCR rendering retains its own bounds. End-to-end memory includes native allocations, so heap limits alone are not hosted RSS acceptance.

The build uses Next's webpack path because Next16.1.6 Turbopack panicked tracing `node:worker_threads`. Explicit Next route traces include parser/OCR workers, PDF.js, every installed CMap, fonts, canvas bindings and build identity. `node scripts/check-vercel-traces.mjs` checks actual traces, including platform-specific native bindings; a trace check is not deployed parser execution.

## Providers remain disabled

Groq text uses the configured `openai/gpt-oss-20b`; grounded prompts, JSON-object mode and result schema validation remain. Combined bounded input/output above the supplied 8000 TPM ceiling is rejected before transmission. Exact durable finite allowance and global pacing are still required.

`src/lib/server/ocr/preview-accounting.ts` constructs the Qwen profile: Groq documents 2048 tokens/image and 131072 context. Framing is a UTF-8 byte upper bound derived from the published Qwen3.8 template, including both image wrappers/labels and the longest reasoning instruction, not an invented tokens-per-character estimate. Input ceiling7000/output1000 and combined8000 bound the supplied account TPM. The model's published template is the accounting source; unexpected usage exceeding the bound is rejected and retains the reservation. Provider-side undocumented template changes remain a reconciliation risk. Configure `OCR_ACCOUNTING_JSON` from this exported object; no owner-authored JSON is needed. No live authorization reference or allowance is created here.

Speech prepares `nova-3-medical` **together with** `AI_SPEECH_LANGUAGE=multi`. Nova3 uses plain `keyterm` hints; retained Nova2/hi injected adapters keep their original keyword behavior. The current transport is bounded recorded PCM WAV over one server HTTP request, not a persistent serverless WebSocket. Existing client capture/segment/final transcript/review behavior is retained. No automatic retry, model fallback or original winning-runtime claim is introduced.

The two reviewed migrations preserve historical Nova2/hi constraints. Therefore the new speech adapter deliberately fails closed until a separately reviewed model-pair extension is applied. The forward SQL is prepared at `rollout/nova3-model-binding.sql`, outside automatic migrations; it is **not hosted applied** or live acceptance. It preserves historical rows and requires an exact live allowance before service-only binding. Do not merely change allowance labels to activate it.

## Bounded future provider acceptance proposal — unconsumed

After explicit owner authorization and confirmed remaining free allowance, allow exactly one text call (`openai/gpt-oss-20b`, synthetic saved transcript only, bounded input<=5000/output<=3000), one OCR call (`qwen/qwen3.8-27b`, one synthetic private page, output<=1000; no external URLs), and one speech call (`nova-3-medical`,multi, one <=10-second synthetic16kHz mono PCM WAV). Maximum3 sends, at least60seconds apart, no retry/fallback, one clinician and one consultation/document scope, authorization lifetime<=1hour. Stop on billing requirement, auth/rate error, unknown outcome, invalid/over-bound usage, schema mismatch or access change. Retain uncertain reservations. Free eligibility/remaining counters must be checked immediately before activation; visible model access or an account credit screenshot alone is not permission to spend. Correct/review all outputs before saving, and restore disabled flags after the bounded run. Live speech additionally requires the reviewed model-binding extension. No such calls were made by this increment.
